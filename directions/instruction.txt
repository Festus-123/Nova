# ============================================================
# 8. THE CORE PROBLEM — DOCUMENT GROUPING
# ============================================================

THIS IS THE MOST IMPORTANT PART OF THE FEATURE.

Do NOT treat:

ONE FILE = ONE INDEPENDENT DOCUMENT

as a universal rule.

Academic material often arrives as a messy collection of pages/images.

Example:

Image 1:

EEE 306
Question 1
Question 2
Question 3
Question 4

Image 2:

No course header.

Question 5
Question 6

Image 3:

CPS 401
Question 1
Question 2
Question 3
Question 4

A naive classifier might produce:

Image 1 → EEE 306
Image 2 → Unknown
Image 3 → CPS 401

That is incorrect.

Nebula should reason that:

Image 1 + Image 2
→ EEE 306

Image 3
→ CPS 401


# ============================================================
# 9. CONTINUATION-PAGE UNDERSTANDING
# ============================================================

Nebula must be capable of identifying continuation pages.

A page does NOT need to repeat its course code/header.

Signals may include:

- question numbering
- continuation of a question
- sequential numbering
- visual similarity
- typography
- page numbering
- subject terminology
- document structure
- neighboring page context
- repeated examination formatting
- previous/next page relationship
- question sequence
- shared instructions
- shared header/footer
- visual layout
- semantic continuity

Example:

Page 1:
CSC 308
1...
2...
3...

Page 2:
4...
5...
6...

Page 3:
7...
8...

Page 4:
CPS 401
1...
2...

The expected grouping is:

GROUP A
Pages 1–3
→ CSC 308

GROUP B
Page 4
→ CPS 401

upload_001.jpg

upload_005.jpg

Possible relationships:

- continuation
- same document
- new document
- duplicate
- unrelated document
- unclear relationship


# ============================================================
# 11. DOCUMENT BOUNDARY DETECTION
# ============================================================

Nebula should identify where one academic document/group ends and
another begins.

For example:

Page 1
EEE 306

Page 2
EEE 306 continuation

Page 3
EEE 306 continuation

Page 4
CPS 401

CPS 401 continuation

Expected:

GROUP 1:
Pages 1–3

GROUP 2:
Pages 4–5

Do not rely solely on course headers.

Do not assume that a new image means a new document.

Do not assume that the absence of a header means an isolated document.

Use contextual reasoning.


# ============================================================
# 12. DOCUMENT CLASSIFICATION
# ============================================================

After grouping related pages/files, determine the requested metadata.

For TACSFON this may include:

material_type
level
school
department
course
session
semester

The engine should extract information from:

- visible headers
- document body
- course codes
- examination instructions
- academic terminology
- page relationships
- neighboring documents
- uploaded batch context
- metadata where useful

Do not invent missing information.

If the evidence is insufficient, return:

status = "isolated"

rather than hallucinating a classification.


# ============================================================
# 13. CONFIDENCE AND EVIDENCE
# ============================================================

The sorting system should distinguish between:

HIGH CONFIDENCE
MEDIUM CONFIDENCE
LOW CONFIDENCE
INSUFFICIENT INFORMATION

Do not use confidence as a fake numerical certainty.

If numerical confidence is implemented, it must have a clear and
consistent meaning.

The response should include useful evidence/reasons where appropriate.

Example:

{
  "status": "isolated",
  "reason": "Course code could not be determined from the document
              or its neighboring pages."
}

Another example:

{
  "status": "classified",
  "confidence": "high",
  "evidence": [
    "Course code appears in first page header",
    "Continuation pages contain sequential question numbers",
    "Final page precedes a new course header"
  ]
}

The goal is to help the human administrator understand WHY Nebula
made the decision.


# ============================================================
# 14. ISOLATION RULE
# ============================================================

If Nebula cannot safely classify a document/group:

DO NOT GUESS.

Return:

status = "isolated"

Possible isolation reasons:

- missing course
- ambiguous course
- missing level
- ambiguous document boundary
- unreadable page
- conflicting metadata
- unsupported content
- insufficient context
- multiple possible classifications
- invalid schema value

An isolated result must include a human-readable reason.


# ============================================================
# 15. REJECTED STATUS
# ============================================================

Nebula may identify files that appear invalid or unusable.

Examples:

- corrupted file
- unsupported format
- completely unreadable content
- empty file
- obviously unrelated content

However:

Nebula must NOT autonomously decide that legitimate but ambiguous
academic material should be permanently rejected.

Use:

isolated

when human review is appropriate.

Use:

rejected

for genuinely invalid/unusable input where appropriate.

Final approval/rejection remains a TACSFON administrator action.

Nebula does NOT publish documents.


# ============================================================
# 16. ADMIN CORRECTION / REPROCESSING
# ============================================================

TACSFON may send an isolated document back to Nebula with additional
information.

Example:

Original result:

status = isolated

reason:
"Course could not be determined."

Admin provides:

TACSFON then sends the document/group again with:

- original document context
- previous classification result
- administrator correction
- additional metadata
- original sorting schema

Nebula should re-evaluate the document using the new information.

Do not treat administrator-provided information as if it came from
the document itself.

Represent it as external/contextual input.

Example conceptual structure:

{
  "additional_context": {
    "course": "EEE 306",
    "source": "administrator"
  }
}

# ============================================================
# 31. ACADEMIC DOCUMENT REASONING
# ============================================================

The model prompt/system logic for document sorting should explicitly
tell the AI:

DO NOT GUESS.

Use evidence from:
- page content
- headers
- question numbers
- course codes
- visual continuity
- neighboring pages
- document structure
- batch context

When evidence conflicts:

- identify the conflict
- lower confidence
- isolate when necessary

When a page has no header:

- inspect its relationship with surrounding pages
- do not automatically mark it unknown

When a new course header appears:

- consider whether it represents a new document boundary
- verify that preceding pages belong to the previous group

When multiple possible groupings exist:

- select the grouping best supported by evidence
- if ambiguity remains significant, isolate the affected group


# ============================================================
# 32. DUPLICATE DETECTION
# ============================================================

Where practical, detect obvious duplicates.

Potential signals:

- cryptographic file hash
- identical file content
- identical page content
- identical document metadata
- repeated uploads within the same request

Do not automatically delete duplicates.

Return duplicate information to the caller.

Example:

status = "duplicate"

or warning:

"Possible duplicate of group_001"

The final decision remains with the client/admin where appropriate.

- preserve useful history where necessary
- avoid stale duplicate facts

Example:

Old:
favorite_language = Python

New:
favorite_language = C++

The system should have a defined strategy for handling updates rather
than storing unlimited contradictory values.

- recovery answers
- security keys

environment secrets from application configuration.

# 48. DO NOT CREATE FAKE INTELLIGENCE
# ============================================================

Do not make the demo appear intelligent by using simplistic rules such
as:

"If filename contains CSC, classify as CSC."

The actual objective is document understanding.

Filename information may be used as one signal where useful, but it
must not be the primary classification mechanism.

The system must work when filenames are:

- IMG_001.jpg
- image2.png
- scan_9382.pdf
- WhatsApp Image 2026...
- document.docx

The content and contextual relationships matter more than filenames.

    ...

    ...

if client == "TACSFON":
    ...

inside the generic sorting engine.

The engine should not know who the client is unless client metadata is
needed for logging/authentication.
